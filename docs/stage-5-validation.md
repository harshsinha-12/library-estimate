# Stage 5 validation and operator run

## Current verification boundary

The model adapters, cost ledger, review gates, offline trainer, security controls, report, and iOS screens can be tested without live Anthropic calls. A generic iOS Simulator build verifies compilation only. The labeled holdout and demo metrics require a new physical capture and an independent manual roster; fixture results must not be reported as device accuracy.

## Security setup before a private network run

Set `LIBRARY_REQUIRE_AUTH=1`, a long random `LIBRARY_OPERATOR_TOKEN`, and a base64 32-byte `LIBRARY_DATA_ENCRYPTION_KEY` on a fresh storage namespace. The iOS operator token lives in the device Keychain. It is sent only to an HTTPS backend URL. The default local HTTP URL remains useful for an unauthenticated development run, but must not be used with an operator token. Use the checked-in `deploy/Caddyfile` and `docs/security-deployment.md` for a private HTTPS run and keep R2 private. Existing plaintext objects must be migrated with `scripts/migrate_object_encryption.py` after reviewing its exact plan ID, or intentionally retained in an isolated plaintext namespace.

`GET /v1/surveys/{id}/evidence?path=...` is the authenticated local equivalent of a signed download URL. Only uploaded package paths and server-derived paths are eligible. Responses have `Cache-Control: no-store`. Bounded access logs omit query strings, token values, and literal survey UUIDs. `DELETE /v1/surveys/{id}` requires `X-Confirm-Delete: {id}`; it removes survey objects, survey-scoped Redis keys, jobs, create/upload/seal idempotency records, and policies trained from that survey. This action is irreversible. `scripts/retention_cleanup.py` lists expired surveys by default and deletes only with `--execute-plan PLAN_ID`; review the exact survey list and plan ID before using it on real data.

iOS seals packages with Data Protection, excludes them from backup, and can require a fail-closed Vision face-redaction pass recorded in `privacy/face-redaction.json`. These controls still need a physical package inspection with redaction enabled. They do not protect transport through a plain HTTP development server or third-party provider retention. Production certificate validation, R2 migration/namespace isolation, key rotation, and provider-retention review remain operational gates.

## Independent zone and holdout

1. Select a controlled 50–100-book zone and freeze the capture protocol, model IDs, prompts, and policy version. Record the physical roster separately from the app. Include two same-ISBN copies, opposite-direction repeat scan, missing ISBN, ambiguous edition, moved book, damaged book, portrait note and close-up, excluded mug, and appraisal item.
2. Capture the zone and record row actual counts, distinct physical copy IDs, ISBNs, excluded items, appraisal items, source photos, and unresolved items. Record physical evidence paths in a separate label JSON file. Use a new, unseen survey for `split: holdout`; do not retune on it.
3. Fetch `/v1/surveys/{id}/report` and save the JSON. Create `ZoneLabels` JSON with `survey_id`, `split`, `labeled_by`, and `cases`. Each case needs `case_id`, `metric`, `expected`, and `physical_evidence_ref`. Supported metrics are `row_count` (with `face_id` and `row_id`), `copy_present`, `copy_isbn`, `copy_excluded`, `copy_appraisal`, `copy_valuation_status` (with `asset_copy_id`), and `same_isbn_separate` (with `copy_ids`).
4. From the repository root, run `python3 -m scripts.evaluate_stage5 report.json labels.json --output metrics.json`. The output includes numerator and denominator for every supplied metric and every case's observed value. Omitted cases are outside the denominator. Archive the report, labels, metrics, model runs, transitions, usage ledger, and provider failures together.
5. Freeze the roster before training with `POST /v1/surveys/{id}/gold-set`: supply `copy_ids` (50–100 unique IDs from the sealed inventory), `case_tags` keyed by copy ID, and `frozen_by`. The API requires all nine cases from `LEFTOVER.md` §4 and stores a hash of the sealed package and roster. This is a roster freeze, not an independent truth label; keep the manual labels in a separate file.
6. Add independent transition labels via `POST /v1/surveys/{id}/independent-labels`. Rewards follow `FINAL-PLAN.md` §13. If a transition records a specialist prediction, classification credit is calculated against the independent truth for that head. A reviewer cannot override that comparison. After at least 10 labeled training transitions with known logging propensities, call `POST /v1/policies/train` with disjoint training and holdout survey IDs. Deterministic live router decisions have no fabricated propensity and cannot enter this fit.
7. `POST /v1/policies/{id}/shadow` scores logged holdout actions only. It reports observed reward, matched-action inverse-propensity reward, action support, and per-head correct/labeled and mean true-class probability. The technique is **offline contextual bandit routing with propensity-weighted linear reward regression**; the specialist heads use **Laplace-smoothed naive Bayes** on logged state features. These small heads are supervised classifiers, not sequential RL or frontier-model fine-tuning. The shadow output cannot establish a causal improvement without adequate action overlap.
8. Inspect `GET /v1/surveys/{id}/auto-accept-audit` for each model auto accept: copy, evidence hash, A/B/Jev output, policy reason, and human overturn authority. Recapture transitions contain a `next_state_id`; after obtaining new evidence, write its `evidence_ref`, SHA-256 hash, and state through `POST /v1/surveys/{id}/rl-successor-states`. The backend verifies the stored bytes and writes the successor record once. No automatic recapture-to-evidence binding exists yet.

Policy artifacts remain in shadow. There is no approved live `policy_id`, canary result, active learned router, or rollback pointer. The physical gold zone and disjoint holdout must precede those gates. One live survey never updates production weights.

The Stage 4 physical 8–10 book row walkthrough and the full Stage 5 demo script in `FINAL-PLAN.md` §23 still require the operator and the phone. Record detected/actual and priced/eligible with numerator and denominator in `SESSION-RUN.md` before closing either stage gate.
